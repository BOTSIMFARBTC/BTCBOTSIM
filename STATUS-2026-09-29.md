## Bug #1: Yahoo data lag on Worker cron

Today's live payload has `entryRef=$84,458.09`. Fetching Yahoo now
shows this value matches **09-27 close**, not 09-28's close ($83,502).
That means at 00:05 UTC 09-29 when Worker fired, Yahoo's API hadn't
yet published the 09-28 bar — Worker fell back to 09-27 (2-day-old data).

**Impact.** Bots score off stale data one-in-N days (depending on
Yahoo's crypto refresh cadence). Entry references are lag-shifted,
which can misprice the current market state.

**Fix options** (pick one, low urgency)
- Move cron from `5 0 * * *` to `30 0 * * *` or `0 1 * * *`
- Add lag detection: warn if `bars.at(-1).date < today - 1 day`
- Switch data source (Coinbase Exchange OHLC is CF-friendly)

Recommendation: **shift cron to `30 0 * * *`** (25 min later, still
well before executor's `*/5` picks up). Zero-risk change; deploy
opportunistically. Or bundle with the R2 archive deploy.
